## 4. How to

### Check the event bus on staging (no AWS console needed)

Nobody on the team has AWS console access. Instead: GitHub → `mapanytime-api`
→ **Actions** → **Diagnose Event Bus (dev)** → **Run workflow**. It posts one
test analytics event, reads the worker's event-bus log lines over SSM and ends
with a verdict:

| Verdict line                          | Meaning                                                   |
| :------------------------------------ | :-------------------------------------------------------- |
| `Working: the event went SNS -> ...`  | All good                                                  |
| `RawMessageDelivery looks OFF`        | The SNS subscription is misconfigured (AWS team fixes it) |
| `The worker cannot read a queue`      | IAM, or a queue named without the `dev-` prefix           |
| `No flush seen for the analytics ...` | Filter policy or subscription is wrong                    |

AWS rule worth knowing: on the dev host, permissions only cover resources
named `dev-…`. Anything else fails with AccessDenied and no explanation.

### Build the staging APK

```sh
cd mapanytime-market-app
cp .env.dev .env.staging   # then set BASE_URL=https://dev.mapanytime.com/api/v1
flutter build apk --release --dart-define=ENV_FILE=.env.staging -t lib/main.dart
```

Output: `build/app/outputs/flutter-apk/app-release.apk` (~167 MB). The
`ENV_FILE` define is what picks the env file; without it the build silently
uses `.env.dev` (localhost). Release builds are debug-signed for now (app #76).

After a build, `lib/l10n/generated/` may show as modified: that's line
endings only. Discard it with `git checkout -- lib/l10n/generated/`.

### Run every check before opening a PR

| Repo | Commands                                                                                        |
| :--- | :---------------------------------------------------------------------------------------------- |
| api  | `npx tsc --noEmit` · `npm run lint` · `npm run format:check` · `npx jest`                       |
| web  | `npm run type-check` · `npm run lint` · `npx prettier --check .` · `npm test` · `npm run build` |
| app  | `dart format --output=none --set-exit-if-changed .` · `flutter analyze` · `flutter test`        |

CI runs the same checks on every PR; a red check means don't merge.

**Web Prettier warning:** 119 files are reported, but with
`--end-of-line auto` every file passes, so it's line endings only. On Windows,
Git converts to CRLF on checkout (`core.autocrlf=true`) and Prettier expects
LF. Not a code problem, and web CI doesn't run Prettier. The fix is a
`.gitattributes` with `* text=auto eol=lf` in web (web #96, P1-8 in
[`NEXT-SESSION.md`](./NEXT-SESSION.md)); until then run
`npx prettier --check . --end-of-line auto` locally.

The API tests print `[Pricing] No ACTIVE PricingConfigurations row matched`
warnings. Those come from tests that deliberately run with no pricing rows;
they're expected, not failures.
