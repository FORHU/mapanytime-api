## 3. Flutter app — runtime hardening (`feat/app-runtime-hardening`)

1. **Tabs stay alive.** The shell is now an indexed stack with five branches.
   Switching tabs no longer destroys the map, so it stops reloading its style,
   GPS and stores on every visit.
   **Visible change:** detail pages (storefront, orders, checkout, rewards,
   notifications…) open full-screen above the tabs, without the bottom bar.
   Back returns to the tab as it was left.
2. **One shared socket.** `lib/core/services/realtime_socket.dart` carries
   stores, vehicles and order notifications on one connection, and
   re-subscribes on every reconnect with a freshly read token.
3. **GPS and sign-out cleanup.**
   - Every streets/satellite toggle leaked a high-accuracy GPS listener; fixed.
   - The map's GPS runs only while the app is open and the Map tab is showing.
   - Driver tracking now stops on sign-out. It still runs in the background
     while signed in — that is intended.
4. **Feature boundaries.** Five shared widgets moved to `lib/shared/widgets`,
   and `OrderConfirmationArgs` moved to `orders/domain`.
   `test/architecture/feature_boundaries_test.dart` fails on any import of
   another feature's widgets or pages.

**For developers:** detail routes are on the root navigator. Reach them with
`context.push`, never `context.go` — `go` replaces the whole stack and rebuilds
every tab.

## 4. Before deploying — in this order

**Someone with AWS access:**

1. **Confirm F113** on a host:
   `docker logs mapanytime-api-worker --tail 20`. Expect "app crashed" or
   "Cannot find module".
2. **Inspect `email.queue`** in the RabbitMQ dashboard. It may hold every email
   since launch, including password-reset codes long expired. Purge it if so —
   the first working worker sends all of it.
3. **Count matured settlements**: `PENDING` with `releaseEligibleAt` in the
   past. All of them become payable on the worker's first hourly run.
4. **Check the `ACCESS_TOKEN_EXPIRY` repository secret** (F98). If it is set,
   15-minute access tokens are not in effect.

**Then ship:**

5. Merge and deploy the **API and web together** — F107 changes the socket
   contract on both sides.
6. Build and publish a **new APK** through App Releases. Older app builds stop
   receiving live notifications once the API change is live; the HTTP
   notification feed still works.
7. After the first deploy with F113, watch the worker's logs for the catch-up
   run.

Not coverable by unit tests — check on a phone before merging
`feat/app-runtime-hardening`:

- [ ] Switch between tabs repeatedly — the map does not reload.
- [ ] Open a store from the map, go back — the map is exactly as left.
- [ ] Live order toasts still arrive; they stop after signing out.
- [ ] The location indicator goes away when leaving the Map tab or
      backgrounding the app.
- [ ] A driver signing out while sharing — the persistent notification
      disappears.
- [ ] Checkout → order confirmation → "Back to Home" lands on Home with the
      bottom bar.
