## ⚠️ Check what `DATABASE_URL` points at before every write

`.env` is gitignored, so `DATABASE_URL` is a property of your machine, not of
the checkout — and on this repo it has been seen pointing at **both** a local
database and the shared **staging** one (`forhu-staging-…-postgres`) on the
same day. Nothing in the working tree tells you which is in effect.

If the check below comes back as anything other than `localhost`, these
ordinary commands are writing to a shared database:

| Command                    | What it actually does here                              |
| -------------------------- | ------------------------------------------------------- |
| `npx prisma migrate dev`   | Applies **to staging**, and offers to reset it on drift |
| `npm run db:setup`         | Same — it is `generate && migrate dev`                  |
| `npx prisma migrate reset` | **Drops and recreates staging**                         |
| `npm run db:seed`          | Seeds **staging**                                       |

Check first — this only reads:

```bash
node -e "require('dotenv').config();console.log(process.env.DATABASE_URL?.replace(/:\/\/[^@]*@/,'://***@'))"
```

Always safe: `npx prisma migrate status`, `prisma validate`, `prisma generate`,
`prisma migrate diff`.

> This is why `20260812150000_analytics_events` carries hand-written SQL rather
> than SQL generated by `migrate dev` — when it was authored, `DATABASE_URL`
> pointed at staging, so `migrate dev` would have applied it straight there.

## Deploying

Run from a shell pointed at staging, with the repo on the commit you intend to
deploy.

**1. See what is pending — this only reads.**

```bash
npx prisma migrate status
```

Expect it to list the four (or five, from this branch) migrations above as not
yet applied. If it reports a _failed_ or _modified_ migration instead, stop and
work that out first; `deploy` will not fix it.

**2. Apply.**

```bash
npx prisma migrate deploy
```

`deploy` is the right verb for a shared database: it applies pending migrations
in order and never prompts, never resets, and never generates new SQL. Do not
substitute `migrate dev`.

**3. Confirm.**

```bash
npx prisma migrate status   # should report the schema up to date
```

**4. Regenerate the client wherever the app runs.**

```bash
npx prisma generate
```

Symptom of skipping this: `tsc` complains about missing Prisma models
(`merchantAds`, `primaryCategory`, `MERCHANTADKIND`, `analyticsEvents`,
property types). The schema is fine; the generated client is stale.

## Telling the team

Anyone with a local database created before the squash has a migration history
that will not match the baseline. They need:

```bash
npx prisma migrate reset
```

**Not `migrate dev`** — it gets confused by the squashed baseline and will
offer its own reset with a more alarming prompt.

Send them this along with it: check your `.env` first. If a teammate's
`DATABASE_URL` also points at staging, `migrate reset` from their machine drops
the shared database.

## After this branch merges

`20260812150000_analytics_events` creates the `AnalyticsEvents` table and the
`ANALYTICSEVENTTYPE` enum. Its SQL is hand-written rather than generated by
`migrate dev` — precisely because `migrate dev` would have written to staging
from this checkout — and was verified byte-for-byte against:

```bash
npx prisma migrate diff --from-empty --to-schema-datamodel prisma/schema.prisma --script
```

It has since been **applied to a real local Postgres and verified**, not just
diffed: 12 columns with the expected nullability, 7 indexes plus the primary
key, all 8 enum values, and 0 foreign key constraints (by design — see the
schema comment). A batch insert, read-back and delete round-tripped, including
`Json` metadata and a null `userId`.

The table is append-only and starts empty, so the migration is fast and carries
no backfill.

The worker gains an `analytics.queue` consumer. It declares its own queue and
DLQ on startup, so no manual RabbitMQ setup is needed — but the worker must
actually be running, or events will pile up in the queue unwritten.
